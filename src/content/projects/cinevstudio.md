## 프로젝트 개요

CineV Studio는 전문적인 3D 제작 지식 없이도 자신의 이야기를 장면으로 만들려는 창작자를 위한 **Unreal 기반 3D 시네마틱 제작 도구**입니다. 캐릭터와 소품을 배치하고 동작·대사·카메라를 편집해 영상으로 출력합니다. 이 프로젝트에서 복잡한 편집 동작을 구현하고, 화면·데이터·복구 상태가 함께 맞도록 개선했습니다.

## 참여 정보

**참여 기간:** 2023.07 ~ 2026.05 (활동 기록 기준)\
**개인 담당:** Action·Timeline·Shot·Camera 개발, UI System 설계·구축 기여, AI 모션 연동, 저장·복구와 CLI 자동화\
**팀 내 역할:** UI/UX Unit 리드(2026.02 기준), 개발·기획·UI 디자인의 우선순위와 담당 범위 조율\
**협업 직군:** 개발·기획·UI 디자인, AI 모션 모델 개발자\
**개발 환경:** Unreal Engine, C++, UMG, Blueprint, DataTable, Git, Perforce

## 본인 기여 요약

- **Timeline·Shot:** 다중 클립 편집, 프레임·화면 좌표 변환과 Undo 오류 수정. 샷 간 리플의 기초를 직접 구현하고, 동료와 함께 기능을 확장했습니다.
- **UI·Camera:** UI System 설계·구축에 기여하고 Scene Editor·Timeline 위젯과 카메라 편집 흐름을 구현했습니다. 동료 코드의 상태 책임과 객체 수명도 리뷰했습니다.
- **저장·CLI:** 백업·롤백, 버전 관리와 출력 초기화 문제를 다뤘습니다. 저장 복구 보강과 씬 편집 Commandlet은 공동 작업입니다.
- **Action·AI 모션:** 동작·자세·상호작용 제작 도구와 NNE 기반 모션 모델 실행·적용 흐름을 개발했습니다.
- **팀 조율:** UI/UX Unit의 목표·우선순위와 직군 간 담당 범위·의존성을 정리했습니다.

## 복잡한 타임라인 편집의 일관성

여러 캐릭터의 동작과 카메라를 함께 편집할 때는 클립 하나의 이동이 다른 클립과 샷의 길이까지 바꿉니다. 사용자는 이동 결과를 미리 확인하고, 한 번의 편집을 되돌렸을 때 관련된 시간 범위도 함께 복구할 수 있어야 했습니다.

어려운 점은 **클립·샷의 시간 범위, 화면 좌표, Undo 기록이 서로 연결돼 있다는 것**이었습니다. 화면에서 위치만 바꾸거나 클립만 복구하면 실제 재생 구간과 표시가 어긋날 수 있었습니다.

### 여러 클립과 샷을 하나의 편집 흐름으로 연결

동작·대사·카메라의 시간 구간인 **Clip**, 클립을 묶는 **Track**, 촬영 단위인 **Shot**을 함께 다뤘습니다. 클립 Drag & Drop, Ctrl/Shift 다중 선택, 동시 이동, Trim과 스냅 가이드를 구현했습니다. 이동할 위치를 미리 보여주고, 리플로 움직일 클립 수가 설정 기준을 넘으면 확인 단계를 거치도록 했습니다.

샷 간 리플의 기초를 직접 구현한 뒤 동료와 함께 기능을 확장해, 클립 이동·길이 변경이 이후 샷의 시간 배치에도 반영되도록 했습니다. ShotBand에서 ShotBlock으로 구조를 전환하는 과정에서는 샷 선택·순서 변경·끝 범위 조절과 복제 Undo/Redo를 개발했습니다.

### 샷 경계에서 시간과 화면 좌표 맞추기

타임라인에는 재생 구간 외에도 고정 폭의 샷 헤더·꼬리 영역과 여백이 있습니다. 프레임에 줌 배율만 곱하면 드래그 위치가 어긋나며, **시간상 같은 경계라도 앞 샷의 끝과 다음 샷의 시작은 화면에서 다른 위치**입니다.

프레임과 화면 좌표의 변환을 공통화하고, 고정 폭 영역과 줌이 적용되는 재생 구간을 나눠 계산했습니다. 경계가 어느 샷에 속하는지도 함께 처리해 재생 헤드·드래그·샷 판정이 같은 좌표 기준을 사용하도록 정리했습니다.

### 편집 단위에 맞춰 복구하고 경계 조건 검토

클립 생성에 따른 리플이 여러 번의 Undo로 나뉘던 문제를 수정해, 한 편집 동작에 속한 변경을 함께 되돌리도록 했습니다. 샷 범위를 복구할 때 현재 클립 길이 제한에 막혀 원래 범위로 줄어들지 않던 문제도 수정했습니다.

동료 코드리뷰에서는 다음과 같이 시간축의 판단 기준을 구체화했습니다.

- **샷 사이의 상태 계승:** 이전 샷의 시작 상태를 가져오던 처리를 검토해, 최종 상태를 평가하는 경로와 새 오브젝트의 기본 초기화 경로를 분리하도록 제안했습니다.
- **리플의 최초 겹침 기준:** 다른 트랙의 가까운 클립이 계산에 섞이지 않도록, 같은 트랙으로 필터링한 뒤 시작 위치로 정렬하는 처리가 반영됐습니다.
- **Undo 완료 처리:** 복구 context와 callback의 책임을 검토하고, 동료와 정상·실패 경로 및 최종 호출 구조를 조정했습니다.

**확인된 결과와 기여:** 클립 생성과 그에 따른 리플 변경을 한 번의 Undo로 함께 되돌리도록 수정했습니다. 재생 헤드·드래그·샷 판정도 공통 좌표 기준을 사용하도록 정리했습니다. 다중 클립 편집과 이 수정들은 직접 구현했으며, 샷 간 리플은 제가 만든 기초를 동료와 함께 확장했습니다. 위 세 경계 조건은 동료 구현에 대한 리뷰 기여입니다.

**검증 범위와 한계:** Undo 리뷰에서는 일부 제안을 되돌리고 최종 구조를 조정했으며, 추가 테스트·디버깅 필요가 남아 있었습니다. 코드 반영을 전체 복구 동작의 안정화 완료로 보지는 않았습니다.

## UI 구조와 상태 책임 정리

캐릭터나 카메라 편집 화면을 바꿀 때마다 화면 표시와 제어를 함께 맡은 위젯을 수정해야 했습니다. 데이터 모델이 ViewModel을 직접 생성·소유하던 구조도 있어, 데이터와 화면의 의존성이 얽혀 있었습니다.

단순히 위젯을 나누는 것만으로는 부족했습니다. **어디에서 데이터를 바꾸고, 누가 화면을 갱신하며, 편집을 끝낼 때 무엇을 정리할지**까지 정해야 새 기능이 같은 기준으로 동작할 수 있었습니다.

### 데이터·화면·편집 제어의 수정 범위 분리

UI System 설계·구축에 기여하고 Scene Editor 적용과 Timeline 위젯 구현을 담당했습니다. UI 생성·접근, 화면 배치, 위젯 전환의 책임을 나누고, View가 필요한 ViewModel을 관리하며 데이터 모델을 연결하도록 정리했습니다.

UMG 위젯은 다음 기준으로 구성했습니다. 실제 위젯 구성을 리뷰하고, 디자이너가 외형을 수정할 속성과 C++·Blueprint 연결 방법도 가이드로 정리했습니다.

- **Base:** 기본 외형·구조와 입력 이벤트 전달을 담당합니다.
- **Component:** 노출된 속성으로 디자인 변형과 프리셋을 조정합니다.
- **View:** 위젯을 조합하고 C++ 편집 동작과 ViewModel을 연결합니다.

### 코드리뷰에서 데이터와 화면의 책임 바로잡기

리플 편집 리뷰에서는 화면의 클립 위치만 바꾸고 실제 데이터 이동을 빠뜨린 부분을 짚었습니다. **클립 데이터를 변경하면 데이터 변경 이벤트로 UI가 갱신되도록** 제안했고, 후속 코드에서 위젯 위치를 직접 바꾸는 중복 처리가 제거됐습니다.

샷 추가 리뷰에서는 공통 추가 함수에 재생 위치 변경이 묶인 문제를 검토했습니다. 이 함수는 사용자 삽입 외에 로드 등에서도 쓰이므로, 재생 위치 변경은 사용자 편집 호출부가 맡도록 제안해 반영됐습니다. 공통 데이터 기능과 화면 동작의 책임을 나눈 사례입니다.

### Camera State의 생성 시점과 종료 처리

카메라 템플릿 선택·생성·편집·종료 흐름과 속성 패널을 재구성하고, 수동 카메라 키·화각 조절·PIP 미리보기 상태 동기화를 구현했습니다. 카메라 키 변경을 Undo/Redo에 연결하고 단축키·버튼·기즈모가 편집 결과를 따라 갱신되도록 개선했습니다.

동료의 Camera State 리뷰에서는 **생성 중인 카메라와 이미 편집 중인 카메라가 사용할 수 있는 데이터가 다르다**는 점을 검토했습니다. 아직 생성되지 않은 클립 데이터를 가정한 처리를 조정하고, 위젯의 약한 참조 보관과 상태 종료 시 미리보기 정리 경로를 제안했습니다. 후속 코드에서 참조 접근·종료 처리와 생성 시 위치·회전 사용 방식의 반영을 확인했습니다.

**확인된 결과와 기여:** 클립 데이터 변경 이벤트로 화면을 갱신하고, 샷 추가 시 재생 위치 변경은 사용자 편집 호출부에서 처리하도록 코드가 정리됐습니다. 편집 종료 시에는 이전 패널의 복원 가능 여부를 확인하고 돌아가도록 개선했습니다. UI System은 공동 설계·구축이며, Scene Editor·Timeline 위젯·카메라 편집과 패널 복귀는 직접 구현했습니다. 데이터 갱신 책임과 Camera State에 대한 변경은 동료 코드리뷰로 기여했습니다.

**검증 범위와 한계:** Camera State 리뷰는 개발 브랜치 반영까지 확인했습니다. 해당 변경의 개별 출시 여부와 모든 UI에 같은 구조가 적용됐는지는 확인하지 않았습니다.

## 저장·자동 출력의 실패 처리

편집한 장면을 다시 열고 영상으로 출력하려면, 실패한 작업의 범위와 복구 방법이 분명해야 했습니다. **여러 파일을 쓰는 저장 과정의 부분 실패**와 **CLI에서만 달라지는 Unreal 실행 환경**을 각각 다뤘습니다.

### 부분 저장 실패에서 기존 파일 복구

씬 파일은 기록됐지만 JSON 설명 파일 저장은 실패할 수 있었습니다. 이런 상태를 성공으로 처리하면 저장된 프로젝트의 구성 파일이 서로 맞지 않게 됩니다.

기존 파일을 먼저 백업하고, 저장 단계에서 실패를 감지하면 백업을 복원하거나 새로 생성한 파일을 정리하도록 구현했습니다. 성공 로그는 모든 저장 단계가 끝난 뒤 기록하도록 했습니다. 프로젝트의 생성·수정 버전도 추적해 저장 데이터의 버전을 확인할 수 있도록 했습니다.

**확인된 결과와 기여:** 저장 도중 실패를 감지하면 기존 파일을 복원하거나 새 파일을 정리하고, 모든 저장 단계가 끝나야 성공을 기록하도록 바꿨습니다. 백업·롤백과 버전 조회·관리는 직접 구현했으며, 동료의 JSON 복구·파일 이동 검사·버전 비교 보강은 리뷰하고 통합했습니다.

**검증 범위와 한계:** 복구 대상은 프로그램이 감지한 저장 실패입니다. 강제 종료나 모든 장애에서의 원자적 저장을 보장한 것은 아닙니다.

### Commandlet에서 누락되는 Gaussian 배경 출력

CLI로 영상을 출력할 때 Gaussian 배경이 빠지는 문제가 있었습니다. 화면에서 보이는 장면이라도 **Commandlet 월드에는 렌더링에 필요한 FXSystem이 준비되지 않을 수 있다**는 실행 환경의 차이가 원인이었습니다.

렌더링을 시작하기 전에 월드와 기존 FXSystem의 상태를 확인하고, 필요한 경우에만 시스템을 생성해 World Scene에 연결하도록 보완했습니다. 이미 시스템이 준비된 경우에는 그대로 사용하고, 준비에 실패하면 출력 작업의 실패로 처리하도록 했습니다.

**확인된 결과와 기여:** Commandlet 출력 전에 필요한 FXSystem을 준비하고, 준비에 실패하면 출력 작업도 실패로 처리하도록 바꿨습니다. 초기화 보완과 조건 검사 코드는 직접 작성했으며, 동료 리뷰를 반영해 관련 판단을 렌더러 내부에 모았습니다.

**검증 범위와 한계:** 초기화 필요 조건을 검사하는 Unreal Automation 테스트 코드를 추가했지만, 전체 테스트 실행 완료는 확인하지 않았습니다. 코드 추가와 실제 실행 검증을 구분합니다.

### 오래 걸리는 자동화 작업의 진행과 실패 확인

씬 편집 Commandlet과 샷 수정 기능은 동료와 함께 구현했습니다. 셰이더 캐시 예열 도구에서는 맵 로드·표시와 셰이더 컴파일 완료를 기다리고, **주기적인 진행 로그·단계별 제한 시간·실패 원인 로그**를 추가했습니다.

영상 출력에서는 PNG 시퀀스를 유지하면서 MP4 인코딩을 명시적인 선택으로 분리했습니다. 인코딩을 생략한 경우도 기록해 자동화 흐름에서 완료와 생략을 구분할 수 있도록 했습니다.

## 추가 개발 기여와 팀 역할

### AI 모션을 편집기 동작으로 연결

WANDR 걷기 생성 모델을 Unreal 편집기에 연결하고 PoseToPose를 포함한 AI 실행 인터페이스를 통합했습니다. **NNE의 모델 생성·입력 텐서 형태 설정·입출력 버퍼 연결·동기 추론을 공통화**하고, 모델별 결과를 캐릭터의 이동과 동작에 적용했습니다. 모델 개발자와 위치·회전 입력 규칙을 맞추고 첫 프레임 회전 불일치, 짧은 이동과 입력 길이 변환 문제를 진단·검증하거나 수정했습니다.

### Action·Stance·상호작용 제작 도구

캐릭터·소품 배치, Action 클립 편집과 대화 패널을 개발하고 IK·Attach를 상호작용에 연결했습니다. ActionSet 저장·불러오기와 동작 데이터 편집기를 구현했으며, 자세 상태인 Stance를 시간 구간으로 관리하고 자세에 맞는 동작을 선택하는 처리를 개발했습니다. 가변 길이 동작을 도입·반복·종료 구간으로 나누는 편집 기능도 구현했습니다.

### UI/UX Unit 리드

2026년 2월에는 개발·기획·UI 디자인 직군이 함께 참여한 작업에서 **목표·우선순위·담당 범위·의존성을 조율**했습니다. 타임라인 조작성, 편집 상태 유지, Undo/Redo와 결과 피드백을 중심으로 개선 범위를 정리했습니다. 직접 구현한 변경에는 타임라인 크기 조절의 실험 기능 제한 제거, 트랙 활성화·클립 추가·더블클릭 편집과 오류 피드백 개선이 있습니다.

## 프로젝트 전체 결과와 회고

Studio 1.4 릴리즈 자료에는 리플 적용 범위 선택, 트랙 순서·접기 상태 유지, Undo/Redo와 실행 결과 안내의 **팀 단위 개선 결과**가 남아 있습니다.

작업 전반에서 중요했던 선택은 **편집 데이터의 변경, 화면 갱신, 실패 시 복구의 책임을 명시하는 것**이었습니다. 공통 데이터 함수에 화면 동작을 묶지 않고, 한 편집 동작의 복구 범위와 자동화 작업의 완료·실패 조건을 각각 정리했습니다. 그 과정에서 호출부와 상태 전환, 복구 경로를 함께 검토해야 했습니다.

개인 기여는 구현 기록과 후속 코드에 반영된 리뷰를 기준으로 구분했고, 릴리즈 화면과 시연은 팀의 제품 동작을 보여주는 자료로 사용했습니다. 코드 반영만으로 실행 검증이나 개별 출시를 확인한 것으로 보지는 않았습니다. 처리 시간·오류율·사용자 생산성의 전후 측정값은 확보하지 않았습니다.
