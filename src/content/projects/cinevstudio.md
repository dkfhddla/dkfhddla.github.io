## 프로젝트 맥락과 역할

CineV Studio는 캐릭터와 소품을 배치하고 동작·카메라·조명을 편집해 영상으로 출력하는 제작 도구입니다. SpicePro의 폭넓은 기능을 씬·컷별 월드 설정과 타임라인에 집중하도록 개편한 제품으로, Unreal 프로그램을 Pixel Streaming으로 웹에 제공했습니다.

시나몬에서 **2021.07–2026.08** 프로덕트 클라이언트 개발을 담당하며 CineV Studio의 개발 과정 처음부터 끝까지 참여했습니다. 장면 배치, Timeline·Shot·Camera와 Action 편집, UI 시스템, 모델 연동과 저장·CLI 출력을 맡았습니다. 팀이 함께 개발한 제품은 사내 테스트와 외부 시연을 거쳐 출시됐고 실제 고객이 이용했습니다.

## 장면 배치와 초기 편집 도구

뷰포트와 드래그 앤 드롭을 통한 캐릭터·소품 배치, 액션 클립 생성·삭제·편집, 타임라인과 퀵 메뉴 개선을 담당했습니다. 액션 데이터의 속성과 대상을 편집하고 등록·불러오기와 런타임 애니메이션 재생을 연결했습니다. 동작의 준비 위치를 지정하는 ReadyPoint 도구와 IK·Attach 구간 편집도 개발했습니다.

타임라인 UI에는 트랙 그룹을 구성하고, 캐릭터 생성·삭제에 따른 갱신과 트랙 선택·스크롤 동기화를 연결했습니다. 클립 이동·트림, ShotBand·샷 범위 조정과 복제를 Undo/Redo 동작과 함께 개선했습니다.

## 샷 경계에서 시간과 화면 좌표 맞추기

**문제:** 샷 사이에는 고정 폭의 UI 영역이 있지만 타임라인 시간은 줌에 따라 달라집니다. 경계를 드래그할 때 화면 위치만으로 계산하면 앞 샷의 끝과 다음 샷의 시작을 구분하기 어려웠습니다. 클립 이동·트림·리플에서는 주변 클립과 샷 범위도 함께 바뀝니다.

**본인 기여와 기술 구조:** 고정 폭 영역을 반영한 프레임·화면 좌표 변환을 공통화하고, 같은 시간 경계에서도 앞 샷 끝과 다음 샷 시작의 화면 위치를 구분해 처리했습니다. ShotBand와 범위 조정, 클립 이동·트림과 Undo/Redo를 연결했습니다. Shot 간 리플의 기초를 직접 구현한 뒤 동료와 함께 기능을 확장했습니다.

**확인된 결과:** 샷 경계의 드래그가 공통 좌표 기준을 사용하고, 편집 범위를 사용자가 선택하는 리플 동작으로 확장했습니다. 한 편집으로 변경된 상태를 Undo/Redo에서 함께 복원하도록 다뤘습니다.

리플 편집은 여러 클립과 트랙에 영향을 주므로 요구사항이 바뀔 때마다 시간 계산과 이동 범위를 반복 확인했습니다. AI를 활용해 웹 UI 프로토타입을 만들고 클립이 밀리는 동작과 트랙 간 연동을 재현했습니다. 이를 바탕으로 **현재 트랙·전체 트랙·특정 트랙**을 대상으로 하는 리플 옵션을 제안했고, 해당 옵션이 제품에 반영됐습니다.

Undo/Redo에서 누락된 동작은 해당 커맨드를 등록하며 보완했습니다. Redo가 객체를 복원한 직후 반환해 후속 콜백을 건너뛰는 문제도 직접 수정했습니다. 콜백에 복원된 객체가 전달되도록 대상 참조를 갱신했습니다.

## UI와 편집 상태의 책임 나누기

**문제:** 화면 표시와 데이터 변경의 책임이 섞이면 클립 위치만 바뀌거나, 공통 함수가 로드 중에도 재생 위치를 바꾸는 등 호출 경로에 따라 동작이 달라질 수 있었습니다. 데이터 모델이 ViewModel을 직접 생성·소유하던 구조도 있어 데이터와 화면의 의존성이 얽혀 있었습니다.

**본인 기여:** Unreal Engine의 CommonUI를 참고해 자체 UI 시스템의 기본 구조를 설계하고, 동료들과 제품 UI를 공동 구축했습니다. 기능·데이터·디자인의 책임을 나누고 Blueprint에 기능 로직이 집중되는 부담을 줄이는 방향으로 정리했습니다. Scene Editor 적용과 Timeline 위젯 구현을 담당하고, View가 필요한 ViewModel을 관리하며 데이터 모델을 연결하도록 구성했습니다.

`UISubsystem`을 레이아웃·레이어와 위젯 생성·표시·전환의 중앙 진입점으로 구성했습니다. C++ Widget Base는 기본 기능과 입력 전달, Blueprint의 Component는 디자인 변형, View는 위젯 조합·런타임 동작과 ViewModel 관리를 맡도록 구분했습니다. Gameplay Tag로 화면을 선택하고, 같은 레이어에 새 위젯을 Push하면 이전 위젯을 숨겼다가 뒤로 가기에서 다시 표시하도록 했습니다.

공통 위젯에 제품 스타일과 Dark/Light 테마를 연결하고, 타임라인의 가로·세로 스크롤 제어와 콤보박스의 아이콘·이미지 표시 기능을 확장했습니다. `StudioHomeWidget`의 생성·표시·제거도 `UISubsystem`이 관리하도록 정리했습니다. 기능 개발자와 UMG 디자인 담당자가 수정할 영역을 구분하기 수월해졌습니다.

이 구조와 실제 위젯의 수정 예시, BindWidget을 통한 C++·UMG 연결 방법을 가이드로 정리했습니다. 화면 표시의 책임과 사용자 편집에 따른 데이터 변경을 구분하는 기준으로 활용했습니다.

## 사이드패널 전환과 편집 종료 복원

사이드 영역과 뷰포트 위젯을 분리하고 Scene 목록 변경의 갱신 이벤트를 보완했습니다. 이후 깊이 계산 중심의 패널 탐색을 Gameplay Tag 관계 중심으로 바꾸고, 주요 화면 교체·하위 화면 진입·형제 화면 교체를 Switch·Push·Pop 동작으로 구분했습니다. 일부 캐릭터·표정 상세 화면에는 뒤로 가기 흐름을 유지했습니다.

클립 삭제나 선택 해제 시 먼저 Default 상태로 전환하면 이전 편집 문맥을 잃어 패널을 복원하지 못하는 문제가 있었습니다. Blackboard의 현재 패널 태그를 UIController가 받아 화면을 전환하도록 연결하고, **이전 패널 복원 → 편집 종료와 Default 전환**을 공통 처리로 묶었습니다. StateBase와 Back 조작으로 복원 경로를 넓히고, 사이드바가 관리하는 패널만 캐시하도록 제한했습니다. 편집 종료 시에는 이전 패널 태그 하나를 저장해 복원하는 방식을 사용했습니다.

## 원격 편집 모드의 상태 소유권

연결 상태·UI 표시·명령 검증이 CVar 중심으로 분산돼 있던 구조에서, 상태 판단의 기준을 `RemoteControlSubsystem`으로 모았습니다. 기존 CVar 유지와 UI 계층이 상태를 소유하는 방식을 검토한 뒤, 연결과 명령을 처리하는 Subsystem이 상태를 관리하고 `UISubsystem`은 변경 이벤트를 받아 화면에 반영하도록 구현했습니다.

첫 연결 시 Streaming 모드로 전환하고 모든 연결이 종료되면 Default로 복귀하는 규칙을 정리했습니다. 연결 중에는 Streaming/God 전환을 허용하고 Default 요청은 거절하도록 했습니다. 명령 입력 검사, 이전·현재 모드 응답과 프로토콜 문서도 같은 규칙으로 맞췄습니다.

## 카메라 클립·키 편집과 구도 유지

카메라 클립·키 편집, 수동·자동 카메라 조작과 관련 패널·퀵 메뉴를 개발했습니다. 카메라 키·화각·PIP 미리보기를 Undo/Redo와 연결하고, 현재 재생 위치를 기준으로 이전·다음 카메라 키를 찾는 기능을 추가했습니다. 자동·수동 카메라 속성, 타깃 ViewModel과 생성·편집·교체 흐름은 동료와 공동 개편했습니다.

타깃 기반 카메라 템플릿은 캐릭터가 바뀌어도 얼굴 등이 정해진 화면 위치에 오도록 구도를 맞추는 기능입니다. 이 영역에서는 버그 수정과 동작 안정화를 주로 담당했습니다.

- 자동 카메라 편집 첫 진입 시 Sequencer가 평가한 프리뷰가 유지되도록 수정했습니다.
- 수동 카메라의 W/S 이동이 줌 슬라이더 범위에 막히는 문제를 수정했습니다.
- 타깃이 없는 카메라의 위쪽 이동을 월드 축·Quaternion 기준으로 처리해 짐벌락 문제를 수정했습니다.
- 로드 후 타깃 평가와 자동 카메라 Bake의 구도가 달라지는 문제를 수정했습니다.
- 로드한 Bake·줌 데이터를 보존하고, ZoomType별 초점거리 해석을 통일했습니다.

## Gizmo·Waypoint·FloorMarker 편집

Gizmo는 씬에서 위치·회전을 조절하는 도구입니다. 기존 Gizmo의 기본 클래스 설정을 통합하고, GameViewportWidget에서 커서가 축 위에 진입하거나 벗어나는 상태를 직접 처리했습니다. 드래그 이동·회전량 표시와 카메라 거리에 따른 크기 보정도 구현했습니다.

WaypointController Actor와 ViewModel을 구현해 경로점 추가·삭제·위치·회전을 애니메이션 섹션 데이터에 반영했습니다. 시작점 변경은 DefaultTransform에도 반영하고, 데이터 변경에 맞춰 화면 표시를 갱신했습니다. C++ 컨트롤러와 Blueprint 디자인 영역을 나누고 Waypoint 전용 Gizmo를 연결했습니다.

Undo/Redo 완료 시 Gizmo의 위치·회전을 동기화하고, 편집 종료 시 이벤트 구독을 해제했습니다. Gizmo·Keep Pose 변경은 Edit 버튼으로 최종 적용되도록 수정했습니다. 바닥 위치를 표시하는 FloorMarker의 생성·표시·상태 관리와 거리별 크기를 보정하는 Billboard도 개발했습니다.

## Action·UnitAction과 캐릭터·소품 상호작용

초기 Action 구조와 시스템을 직접 구현했고, 이후 동료와 논의하며 **동작의 의미를 표현하는 MetaAction**과 **실제 애니메이션을 표현하는 UnitAction**으로 발전시켰습니다. 사용자가 앉기 동작과 의자를 선택하면, 소품의 태그·종류와 상황에 맞는 앉기 애니메이션을 선택하는 구조입니다.

ActionSet 저장·불러오기, UnitAction 데이터 편집, 대상 클래스 타입 필터와 Stance 상태를 개발했습니다. 동작·대상·포즈·거리 조건에 따른 후보 선택 규칙을 보완하고, 이전 액션과 포즈가 다르다는 이유로 후보를 제외하던 처리를 점수 부여 방식으로 바꿨습니다. UnitAction DataTable의 타깃 유형·부위 우선순위·애니메이션 참조를 검사하는 검증 도구와 실행 버튼도 구현했습니다. 가변 길이 동작은 도입·반복·종료 구간으로 나누어 편집하도록 했습니다.

IK·Attach 구간과 캐릭터·소품 상호작용도 담당했습니다. 같은 소품을 다시 Attach할 때 위치가 튀는 문제는 Attach 시작 시점에 기존 Transform 구간을 끝내, 위치 애니메이션과 Attach가 동시에 적용되지 않도록 수정했습니다.

다인용 의자는 좌석별 점유 상태를 관리해 같은 자리를 중복 사용하지 못하도록 하고, 다른 캐릭터는 빈자리에 앉을 수 있도록 구현했습니다. 침대는 앉기·눕기의 점유 상태를 나누고, 점유를 타임라인의 시간 구간별로 관리했습니다.

액션 연결·블렌딩 작업에서는 링크의 구간·길이·블렌딩 상태와 갱신 여부를 보여 주는 디버그 시각화 도구를 만들었습니다. 동료가 링크 시스템의 동작을 파악하고 수정하는 데 활용했습니다.

## AI 모션 모델 실행과 결과 적용

WANDR은 Waypoint 동선을 바탕으로 걷기 애니메이션을 생성하고, PoseToPose는 액션·클립 사이를 잇는 애니메이션을 생성합니다. 모델 개발은 별도 담당자가 맡았고, 본인은 **Unreal 안에서 모델을 실행하고 결과를 받아 캐릭터에 적용하는 파이프라인**을 구현했습니다.

NNE 모델 생성·입력 형태·입출력 버퍼·추론 호출을 공통화했습니다. 모델 출력과 Unreal 좌표계의 차이를 다루며 모델 개발자와 입출력 의미를 확인하고, 샘플 출력과 실제 적용 결과를 반복 점검했습니다. 첫 프레임의 추가 회전은 입력·모델 입출력·클라이언트 변환을 비교해 진단했고, 모델 담당자가 수정한 결과를 제품에서 검증했습니다.

## 저장 버전 관리와 실패 복구

**문제:** 업데이트로 저장 구조가 달라지면 작업물이 어느 버전에서 생성·수정됐는지 추적할 필요가 있었습니다. 씬과 메타데이터를 여러 파일로 저장할 때 일부 단계만 성공하면 구성 파일이 맞지 않을 수도 있었습니다.

**본인 기여:** 기존 파일을 백업하고 저장 실패를 감지하면 복원하거나 새 파일을 정리하는 처리를 구현했습니다. 모든 저장 단계가 끝난 뒤 성공을 기록하고 생성·수정 버전을 추적했습니다. 동료의 JSON 복구·파일 이동 검사·버전 비교 보강은 리뷰하고 통합했습니다.

캐릭터 정보 누락 복구와 빈 프로젝트의 원격 로드 크래시 방지 작업도 담당했습니다. 파일별 백업·복원과 저장 단계의 성공·실패 처리를 통해 감지된 저장 실패에 대응하도록 했습니다.

## StoryToMovie와 씬 편집 CLI

StoryToMovie는 아이디어·스토리를 AI가 씬 구성용 JSON으로 만들고, Unreal에서 배경·소품·캐릭터·액션·대사를 설정하는 흐름입니다. 액션은 MetaAction으로 전달받아 상황에 맞는 UnitAction을 선택합니다.

본인은 저장된 씬을 수정하는 **CinevEditScene CLI 구현**을 담당했습니다. 캐릭터·소품·액션 변경과 Shot 추가·제거·수정을 지원하고, 샷 편집 기능은 동료와 함께 구현했습니다. 비동기 큐 관련 작업과 큐 종료 문제 수정도 수행했습니다. JSON을 직접 수정해 CLI로 적용한 뒤 CineV Studio에서 씬을 열어 변경 결과를 확인하며 검증했습니다.

## 셰이더 캐시 예열과 영상 출력

스트리밍 장비가 바뀌어 셰이더 캐시가 사라지면 배경 머티리얼과 3D 장면이 제대로 표시되지 않는 문제가 있었습니다. 이를 위해 **CinevWarmShaderCache CLI를 직접 구현**했습니다. 전체 씬 또는 `-Maps`로 지정한 씬을 대상으로 로드·표시 대기·안정화·셰이더 작업 완료 대기·해제를 처리했습니다.

진행 로그와 시간 제한, 씬별 성공·실패·소요 시간·실패 원인을 기록했습니다. NVIDIA DXCache의 파일 수·용량·수정 시각을 실행 전후 비교하고 사용법과 종료 코드를 문서화했습니다. 예열을 적용한 뒤 저장된 씬이 정상적으로 로드되는 것을 확인했습니다.

CLI 영상 출력은 화면 실행과 월드 초기화 조건이 달랐습니다. Gaussian 배경이 빠지는 문제에는 렌더링 전 World·FXSystem 상태를 확인하고, 필요한 경우 FXSystem을 생성해 Scene에 연결하도록 보완했습니다. 준비 실패는 출력 실패로 처리하고, 초기화 조건을 검사하는 Unreal Automation 테스트 코드를 추가했습니다.

MP4 내보내기 옵션과 렌더링 처리도 담당했습니다. `-RenderVideoMp4`를 지정할 때 루트 MP4를 생성하도록 분리하고, PNG 시퀀스와 메타데이터 출력은 유지했습니다.

## 코드 리뷰에서 다룬 상태와 동작 규칙

동료 구현을 리뷰하며 편집 데이터·UI 표시·객체 수명·Undo/Redo의 책임과 기대 동작을 검토했습니다.

- **정상 상태와 실패 구분:** ActorSequence가 아직 생성되지 않은 정상적인 Actor를 실패로 처리하는 경우를 지적하고, 콜백 실행 책임과 중복 캡처·전달을 함께 검토했습니다.
- **Shot 상태 계승:** 다음 Shot은 이전 Shot의 최종 상태를 이어받아야 한다고 제안했습니다. 새 Actor의 기본값 설정과 Shot 초기화의 목적을 구분했고, 동료가 초기화 처리를 개선했습니다.
- **데이터와 UI 갱신:** 위젯만 이동하고 실제 Section은 이동하지 않는 누락을 지적했습니다. 직접 화면 위치를 바꾸는 대신 **클립 데이터 변경 → 변경 이벤트 → UI 갱신**을 사용하도록 제안했고, 동료가 수정했습니다.
- **사용자 편집의 부수 효과:** AddShot은 로드·StoryToMovie에도 쓰이므로 재생 위치 이동은 사용자 Insert 호출부에서 처리하도록 제안했습니다.
- **패널 복원과 수정 범위:** 액션 추가 뒤 패널이 초기화되는 현상을 직접 재현하고, 타깃 유무에 따른 패널 유지·복원과 생성 클립 선택 규칙을 동료와 조율했습니다.
- **생성과 실패 처리:** 객체 생성·목록 추가의 책임과 변경 이벤트 누락을 검토하고, 복구 가능한 실패로 프로그램이 종료되지 않도록 요청했습니다.
- **선택과 미리보기 수명:** 미리보기 객체의 약한 참조·캐시·종료 정리, 다중 선택 보존, Undo/Redo를 통한 변경과 Gizmo 연결·해제의 대칭성을 검토했습니다. State별 책임과 Registry를 통한 위젯 조회도 제안했습니다.
- **점유와 복원 경로:** 점유 설정뿐 아니라 해제도 설정값으로 표현하도록 요청했습니다. 이미 조회한 ActorSequence를 전달해 중복 조회를 줄이고, 조건 검사 순서를 개선하도록 제안했습니다.
- **호환성과 판단 조정:** 로드 처리·명명·오타를 확인하고 직렬화 변수명을 유지해야 하는 이유를 검토했습니다. 카메라 삭제 처리의 대안을 논의한 뒤 동료 설명을 바탕으로 기존 방식을 유지하기도 했습니다.
